# Архитектура nikki-fleet

## Компоненты

| Компонент | Где | Язык | Что делает |
|---|---|---|---|
| `nikki_fleet/ops.uc` | роутер, `/usr/share/ucode/` | ucode | вся работа с Nikki: профили, проверка `mihomo -t`, резервные копии, перезапуск, откат, API mihomo, статус |
| `nikki-fleet` | роутер, `/usr/bin/` | ucode | CLI и агент (служба `/etc/init.d/nikki-fleet`) |
| `luci.nikki-fleet` | роутер, rpcd | ucode | методы для LuCI поверх `ops.uc` |
| `luci-app-nikki-fleet` | роутер, LuCI | JS | страницы «Конфигуратор» и «Удалённое управление» |
| `configurator/index.html` | везде | HTML/JS | общий конфигуратор: отдельный файл, в LuCI и в панели |
| `panel` | сервер | Go (только stdlib) | веб-панель, API, очередь команд, история |

Один и тот же код (`ops.uc`) используется и локально в LuCI, и удалённо агентом, поэтому правила безопасного сохранения одинаковы везде.

## Конфигуратор и «хост»

Конфигуратор — один HTML-файл. Если его открыть сам по себе, он работает с файлами и с API mihomo напрямую. Если его встроить в iframe, родительская страница передаёт ему `window.NF_HOST`:

```js
window.NF_HOST = {
  kind: "luci" | "panel",
  title: "имя роутера",
  canWrite: true,
  listProfiles(),                          // → {active:{kind,name}, profiles:[…]}
  readProfile(kind, name),                 // → текст YAML
  writeProfile(kind, name, content, opts), // → результат write_profile (см. ниже)
  api(method, path, body),                 // → {ok, code, data} — запрос к API mihomo
};
```

В LuCI эти функции вызывают rpcd-объект `luci.nikki-fleet`, в панели — команды агенту.

## Безопасное сохранение профиля (`write_profile`)

1. Проверка имени: только `^[A-Za-z0-9_.@-]+\.ya?ml$` внутри `/etc/nikki/profiles` или раздел подписки.
2. `mihomo -d /etc/nikki/run -f <временный файл> -t`. Ошибка — ничего не меняется, возвращается вывод mihomo.
3. Резервная копия в `/etc/nikki-fleet/backups/` (хранятся последние 10 для каждого профиля).
4. Атомарная запись (временный файл + rename).
5. Если указано, профиль делается активным (`uci nikki.config.profile`).
6. `/etc/init.d/nikki reload` и ожидание ответа API mihomo (`/version`).
7. Нет ответа — восстановление копии и прежнего активного профиля, повторный перезапуск. В ответе `rolled_back: true` и хвост лога mihomo.

Результат: `{ok, stage: validate|test|write|written|reloaded|reload, error?, output?, backup, rolled_back?, recovered?}`.

## Протокол агента

Агент открывает только исходящие HTTPS-соединения к панели.

### Подключение

```
POST /api/agent/v1/enroll
{"code": "K7QD-M2XA", "info": {"hostname": "…", "board": {…}, "fleet_version": "0.1.0"}}
→ 200 {"router_id": "…", "token": "<64 hex>"}
```

Код одноразовый, живёт 30 минут, создаётся владельцем в панели. Панель хранит только SHA-256 токена.

### Long-poll

```
POST /api/agent/v1/poll
Authorization: Bearer <token>
{"agent_version": "0.1.0",
 "status": {…} | null,                   // полный статус раз в status_interval секунд
 "results": [{"id": "…", "ok": true, "data": {…}}],
 "events":  [{"type": "auto_rollback", "message": "…"}]}
→ 200 {"commands": [{"id": "…", "type": "profile.write", "args": {…}}], "status_interval": 60}
```

Панель держит запрос до 40 секунд или отвечает сразу, как только для роутера появилась команда. Результаты приходят в следующем запросе (агент отправляет его сразу после выполнения). `401` — роутер удалён из панели, агент перестаёт стучаться на 10 минут.

### Команды

| Команда | Минимальная роль | Аргументы |
|---|---|---|
| `status`, `agent.ping` | просмотр | `full` |
| `profiles.list`, `profile.read`, `profile.test`, `backups.list`, `logs.tail` | просмотр | `kind`, `name`, `content`, `which`, `lines` |
| `traffic` | просмотр | `limit` — сводка `/connections`: самые активные соединения (по умолчанию 300) с нужными полями и имена устройств из DHCP |
| `proxies` | просмотр | — сжатый `/proxies` + `/providers/proxies`: группы в порядке конфига, тип, UDP и последняя задержка узлов, подписки |
| `fleet.update` | владелец | — запускает в фоне установщик панели (`/install.sh`), который обновляет пакеты nikki-fleet; журнал — `logs.tail which=update` |
| `mihomo.api` GET | просмотр | `method`, `path`, `body` |
| `mihomo.api` другие методы | редактор | |
| `profile.write`, `backup.restore`, `nikki.reload`, `subscription.update` | редактор | |

Агент дополнительно запрещает удалённо `PUT /configs`, `POST /restart`, `POST /upgrade*`, `POST /configs/geo`: конфиг меняется только через `profile.write` — с проверкой, копией и откатом.

Команда, которую агент не успел забрать до таймаута, отзывается: когда роутер вернётся в сеть, устаревшее изменение не применится.

### Автооткат при потере связи

После успешного `profile.write` с перезапуском агент записывает `/etc/nikki-fleet/pending.json` со сроком 3 минуты. Первый успешный запрос к панели подтверждает изменение и удаляет файл. Если срок истёк, а панель недоступна (например, новый конфиг сломал маршрут до неё), агент восстанавливает предыдущую версию и сообщает о событии `auto_rollback`, когда связь вернётся. Проверка срабатывает и после перезапуска агента.

## Панель

- Состояние — один JSON-файл (`state.json`, атомарная запись), история конфигов — файлы `configs/<router>/<version>.yaml` (последние 50 на роутер). Хранилище спрятано за методами `Store`, его можно заменить на SQL.
- Пароли — PBKDF2-SHA256 (210 000 итераций), сессии — случайный токен в cookie `HttpOnly`, `SameSite=Lax`, в базе только хэш.
- Изменяющие запросы требуют заголовок `X-NF: 1` (защита от CSRF).
- Ограничение попыток входа, регистрации и подключения роутеров.
- Роли: владелец (всё, доступы, удаление), редактор (изменение конфига), просмотр. Администратор управляет пользователями и регистрацией, но **не** видит чужие роутеры.
- Журнал действий по каждому роутеру.

## Зеркало пакетов

Многие роутеры стоят за фильтрацией, где недоступны `nikkinikki.pages.dev` и иногда GitHub. Панель обычно работает на VPS с открытым доступом, поэтому служит зеркалом:

- `GET /dl/nikki-fleet/assets.json` — список пакетов последнего релиза nikki-fleet;
- `GET /dl/nikki-fleet/<файл>` — пакет nikki-fleet из последнего релиза;
- `GET /dl/nikki/nikki_<arch>-<branch>.tar.gz` — архив пакетов Nikki из его релиза на GitHub.

Разрешён только фиксированный набор имён файлов (не открытый прокси), файлы кэшируются в `<data>/mirror`, есть ограничение запросов с одного IP. Установщик пробует источники по порядку: официальный репозиторий Nikki → релиз на GitHub → панель.
